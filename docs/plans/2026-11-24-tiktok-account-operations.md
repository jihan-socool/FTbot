# FTbot TikTok 账号运营方案：三个 bot 共用一个浏览器

状态：方案草稿（2026-11-24），基于代码阅读，未在真实 TikTok 账号上实测。

## 1. 目标与范围

- 运营 **一个** TikTok 账号，由 **三个 bot** 分工：读数据、回评论、发私信。
- 私信只发给 **在视频下留过评论的人**，频率低，不做批量触达。
- 软件部署在店主本地电脑，bot 通过本地浏览器操作 TikTok。
- 提供看板，让店主看到 bot 在做什么，以及账号经营情况。

不在本文范围：多账号矩阵、视频制作与发布、店铺后台（可作为后续扩展）。

已确认的前提：

| 项 | 店主的回答 | 对方案的影响 |
|---|---|---|
| 账号类型 | 普通账号 | 不依赖官方 API，数据、评论、私信全部走浏览器 |
| 评论量 | 最多几百条（本文按每天计），只处理有价值的 | 评论 bot 先整批读取并分类，只对有价值的评论做回复动作（4.4） |
| 语言 | 按对应的销售国家匹配 | 增加一张市场表，回复和私信按市场的语言写（4.5） |

## 3. 核心问题：三个 bot 共用一个浏览器、各用一个标签页，能不能实现

**能。三个 bot 轮流使用同一个浏览器，每次一个 bot 用完一整轮再换下一个；用 New browser 时，每个 bot 的标签页由代码保证互不干扰。**

### 3.1 共用是怎么工作的

- 在 Settings 里建一个共享 profile（例如「TikTok 主账号」），把三个 bot 的浏览器都设为它。三个 bot 用的就是同一个 Chrome、同一次登录。
- 浏览器是一个「席位」：某个 bot 的一轮任务第一次调用浏览器时占下它，这一轮结束时释放。
- 另一个 bot 此时调用浏览器会等待。等不到时，它收到「浏览器正在被使用，请再调用一次」的回答，这次调用不会执行。
- 占用方超过 60 秒没碰浏览器、且有别的 bot 在等时，席位会让给等待的 bot。原占用方下一次调用会被拒绝一次，并被告知页面可能变了。
- 所以这不是真并行，三个 bot 也不会一步一步交替操作。对同一个 TikTok 账号来说，这更像真人，也更安全。

### 3.2 标签页：两套引擎的区别

| | 默认引擎（agent-browser） | New browser（设置里打开） |
|---|---|---|
| 标签页归属 | 没有归属，所有标签页共用 | 每个标签页属于第一个使用它的 bot；页面自己弹出的标签页归打开它的那个 bot |
| 不带 `tab` 的调用 | 作用在最前面的标签页，可能是上一个 bot 留下的 | 作用在自己的标签页；最前面是别人的标签页时，回到自己上次用的那个 |
| 操作别人的标签页 | 可以（靠提示约束） | 被拒绝，包括读取、点击、切换、关闭 |
| 没有自己的标签页时 | 需要自己新开 | 先接手一个没人用过的标签页，没有就新开 |
| 关闭整个浏览器 | 会关掉所有 bot 的页面（靠提示约束） | 别的 bot 还有标签页时，只关自己的 |
| 系统提示 | 告知和谁共用；要求先列出标签页、切到自己的、不动别人的 | 告知和谁共用；说明每个 bot 有自己的标签页 |

建议运营账号时打开 New browser（Settings 里的实验性开关）。两套引擎保存的登录态不通用，切换会关闭已打开的浏览器，所以先打开开关，再登录 TikTok。

### 3.3 仍然是全局的行为

| 行为 | 后果 |
|---|---|
| 店主接管任意一个标签页，整个 profile 的 bot 调用都被拒绝 | 过验证码时三个 bot 都暂停（这是合理的） |
| 重启浏览器的工具会把所有页面关回一个空白页 | 只在工具明确要求时才用 |
| 浏览器空闲 10 分钟自动关闭，下次调用时重新打开页面，但标签页编号会变，归属清空 | 每个 bot 开工时先打开自己的页面，不依赖记住的编号 |
| 同一 profile 最多 8 个标签页 | 三个 bot 每个固定用一到两个 |
| 实时画面显示最前面的标签页 | 画面跟着当前占用浏览器的 bot 走 |

## 4. 推荐方案

### 4.1 总体结构

```text
                店主（Mac 或 iPhone）
                        │
                     主 bot ── 汇总、审批、看板
          ┌─────────────┼─────────────┐
       数据 bot       评论 bot       私信 bot
          └─────────────┼─────────────┘
          共享 profile「TikTok 主账号」（一个 Chrome，一次登录）
           标签页 A        标签页 B       标签页 C
           数据分析页      评论管理页      私信收件箱
                        │
                   账号台账（共享数据）
                        │
                      看板
```

### 4.2 三个 bot 的分工

| bot | 做什么 | 什么时候跑 | 固定页面 |
|---|---|---|---|
| 数据 bot | 读取每条视频的播放、点赞、评论数、分享、粉丝变化，写入台账，更新看板数据 | 定时，每天 2 次，避开评论高峰 | TikTok Studio 数据分析页 |
| 评论 bot | 读新评论并分类（4.4），只回复有价值的，把有购买意向的人记为「可私信」 | 定时，每 30–60 分钟 | 评论管理页 |
| 私信 bot | 只处理台账里「可私信」的人：按市场语言发第一条私信，之后跟进对方的回复 | 由评论 bot 的结果触发，外加每小时看一次收件箱 | 私信收件箱 |
| 主 bot | 接收店主指令，分派给三个 bot，处理审批，生成日报 | 店主对话时，以及每天一次日报 | 不操作 TikTok |

为什么是三个 bot 而不是一个 bot 跑三个定时任务：每个 bot 一次只能跑一个任务。一个 bot 抓数据的时候，就没法回评论。三个 bot 各有自己的指令和记忆，可以交替使用浏览器。

### 4.3 浏览器使用规则

共用浏览器的 bot 会在系统提示里自动得到共用说明（和谁共用、等待时怎么做、标签页怎么用），不需要店主手写。每个 bot 的指令里再补充这几条：

1. 开工先用 `agent_browser_open` 打开自己的固定页面，不依赖上次记住的标签页编号。
2. 一轮任务里的浏览器操作尽量连续做完。需要长时间思考或写台账时，先把浏览器上的事做完，因为 60 秒不碰浏览器，席位可能让给别的 bot。
3. 收到「浏览器被别的对话用过」或「浏览器被重新打开」的提示时，重新打开自己的页面再继续。
4. 只有在工具明确提示必须重启时才重启浏览器。
5. 遇到验证码或登录过期，调用 `request_sign_in` 请店主接管，不自己尝试。

### 4.4 评论筛选

评论 bot 每次运行分两步，这样几百条评论里只有少数会产生浏览器操作：

1. **读取和分类**：整批读取新评论的文字，逐条归类，全部记入台账（用于去重和统计）。这一步不点击、不输入。
2. **处理**：只对「有购买意向」和「产品问题」两类做回复。

| 类别 | 例子 | 处理 |
|---|---|---|
| 有购买意向 | 问价格、起订量、运费、能否发到某国、怎么下单、要产品目录 | 公开回复，并记为「可私信」 |
| 产品问题 | 尺寸、材质、颜色、用法、有没有现货 | 公开回复，不私信 |
| 投诉或售后 | 质量问题、没收到货、要退款 | 不自动回复，标为「需人工」 |
| 普通互动 | 夸奖、表情、@朋友 | 不回复 |
| 广告、同行、无意义内容 | 推广链接、刷屏 | 忽略 |
| 拿不准 | 看不懂、有歧义 | 标为「需人工」 |

- 分类标准和各类的回复口径写进评论 bot 的指令，店主可以随时改。
- 去重：同一条评论只处理一次。页面上读不到评论 ID 时，用「视频 + 用户 + 内容 + 时间」作为唯一标识。
- 量级估算（假设，未实测）：如果有价值的评论占一到两成，每天是几十条回复，排队使用一个浏览器足够。

### 4.5 语言匹配

回复和私信的语言由销售国家决定，用一张市场表配置：

| 字段 | 说明 |
|---|---|
| 国家 | 销售目标国家 |
| 语言 | 该国使用的回复语言 |
| 货币与报价口径 | 报价用什么货币，是否可以直接报价 |
| 发货信息 | 能否发货、大致时效和运费说法 |
| 后续联系方式 | 例如 WhatsApp、邮箱、独立站链接 |

匹配规则（默认设定，可改）：

1. 每条视频标注它对应的销售国家，不标注时用账号的主市场。
2. 回复语言 = 该视频销售国家的语言。
3. 评论用的是另一种语言，且这种语言在市场表里：按评论的语言回复，并按那个国家的发货信息作答。
4. 评论的语言不在市场表里：标为「需人工」，不自动回复。
5. 私信沿用触发它的那条评论所用的语言，整段对话保持一致。

店主看不懂的语言：审批卡片和看板上，每条回复和私信旁边附一份中文译文，店主按译文审批。

普通账号看不到评论者所在国家，所以只能靠视频的市场标注和评论本身的语言来判断。

### 4.6 私信规则

| 规则 | 设定 |
|---|---|
| 对象 | 只限在本账号视频下留过评论的用户 |
| 触发条件 | 评论被归为「有购买意向」（见 4.4），或店主手动指定 |
| 去重 | 同一用户只发一次首条私信；对方没回复不追发 |
| 前置动作 | 先在评论区公开回复一次，再发私信 |
| 语言 | 与触发它的评论回复一致（见 4.5） |
| 上限 | 每天设一个保险上限（建议起步 20 条），正常情况下远低于它 |
| 审批 | 上线头两周，首条私信先给店主确认（附中文译文）；稳定后改为只审「需人工」的 |
| 发不出去时 | 记录原因，改为在评论区引导对方主动私信 |

待确认：TikTok 对「向非互关用户发私信」有限制，具体取决于对方的隐私设置。普通账号能否给评论者发出首条私信，需要在真实账号上测一次，再定最终流程。发不出去的情况按上表最后一行处理。

### 4.7 账号台账（bot 之间靠它协作）

三个 bot 不直接互相传话，而是读写同一份台账。这样不会重复回复，看板也有统一的数据来源。

| 表 | 主要字段 | 谁写 | 谁读 |
|---|---|---|---|
| markets | 国家、语言、货币与报价口径、发货信息、后续联系方式 | 店主（通过主 bot） | 评论 bot、私信 bot |
| videos | 视频 ID、标题、发布时间、销售国家 | 数据 bot | 全部 |
| video_metrics | 视频 ID、采集时间、播放、点赞、评论数、分享、收藏 | 数据 bot | 看板 |
| account_metrics | 日期、粉丝数、主页访问、总播放 | 数据 bot | 看板 |
| comments | 评论 ID、视频 ID、用户、内容、时间、语言、类别、状态（不处理 / 待回复 / 已回复 / 需人工）、回复内容、回复的中文译文 | 评论 bot | 私信 bot、看板 |
| dm_threads | 用户、来源评论 ID、语言、状态（待发 / 待审批 / 已发 / 对方已回 / 已转人工 / 发送失败）、最近消息时间 | 评论 bot 建，私信 bot 更新 | 看板 |
| bot_runs | bot、开始时间、结束时间、结果、处理条数、错误 | 每个 bot | 看板 |

现状限制：每个 bot 的数据库是自己的，没有现成的共享表。两种做法：

- **第一阶段（不改代码）**：由数据 bot 持有台账数据库，另外两个 bot 把结果写到一个约定的共享文件夹里的文件（每个 bot 只写自己的文件，避免同时写同一个文件），数据 bot 每次运行时合并进台账。需要先验证非主 bot 能否读写同一个文件夹。
- **第二阶段（改代码）**：增加一个「账号台账」数据库，绑定在共享 profile 上，三个 bot 都能通过 Data 工具读写。

### 4.8 看板

分两块，放在同一个页面上。

**运行看板**（bot 在做什么）

- 每个 bot 一张卡片：状态（空闲 / 运行中 / 等待浏览器 / 等待店主）、当前任务、上次运行时间和结果、下次运行时间。
- 浏览器状态：是否登录、当前谁在用、是否被店主接管。
- 待办：待审批的私信（附中文译文）、标为「需人工」的评论、需要店主过的验证码。
- 今日计数：已回复评论数、已发私信数 / 上限、失败次数。

**经营看板**（账号怎么样）

- 指标卡：粉丝数及日变化、近 7 天播放量、互动率、评论回复率、私信回复率。
- 视频表：每条视频的播放、点赞、评论、分享，按发布时间或播放量排序。
- 评论漏斗：新评论 → 有价值 → 已回复 → 有购买意向 → 已私信 → 对方已回复。
- 按销售国家拆分：各国的评论数、有购买意向数、私信回复率。
- 趋势图：粉丝和播放按天。

实现：第一版用仓库已有的 `data-dashboards` skill。数据 bot 每次运行后导出数据到看板文件夹，页面设为 `live`，会自动刷新，不需要写新界面。之后再把运行看板做进应用里，对应 README 中 Planned 的「一屏看所有 bot」。

## 5. 实施步骤

### 第一阶段：配置和指令

1. 在设置里打开 New browser，再建共享 profile「TikTok 主账号」，店主手动登录一次。
2. 建三个 bot，浏览器都指向该 profile，写入各自的分工指令、4.3 的浏览器规则、4.4 的评论分类标准。
3. 填市场表（4.5），给现有视频标注销售国家。
4. 写三个 skill：读数据、回评论、发私信（页面在哪、怎么读、怎么判断成功）。
5. 配定时任务：数据 bot 每天 2 次，评论 bot 每 30–60 分钟，私信 bot 每小时。错开分钟数。
6. 建台账和看板页面。
7. 私信全部走店主审批，跑一到两周，看等待浏览器的时长、验证码出现的频率，以及分类和译文的准确度。

### 第二阶段：代码改动

| 改动 | 说明 | 状态 |
|---|---|---|
| 标签页归属到 bot（New browser） | 不带 `tab` 时用自己的标签页；别人的标签页被拒绝；关闭只关自己的 | 已完成 |
| 提示 bot 正在共用浏览器（两套引擎） | 系统提示里说明和谁共用、等待时怎么做、标签页怎么用 | 已完成 |
| 共享台账 | 见 4.7 第二阶段 | 未做 |
| 实时画面按 bot 固定 | 每个 bot 的面板只显示它自己的标签页 | 未做 |
| 空闲关闭后保留标签页归属 | 重新打开时按地址把标签页还给原来的 bot | 未做 |

### 第三阶段：扩展

- 应用内的运行看板（一屏看所有 bot）。
- 多账号时，每个账号一个 profile，并加上按 profile 设置出口代理。
- 店铺后台另开一个 profile，与 TikTok 操作并行。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 浏览器自动化回评论、发私信可能违反 TikTok 使用条款，有限流或封号风险 | 低频、去重、只回复有价值的评论、私信人工审批、每日上限。普通账号按不能用官方 API 设计（官方 Business API 面向企业号，这一点我没有核实） |
| 验证码、登录过期 | bot 请店主接管；看板上显示为待办；此时三个 bot 都会暂停 |
| TikTok 页面改版导致读错、点错 | skill 里写明「怎么判断成功」；失败记入 bot_runs，连续失败时暂停该 bot 并通知店主 |
| bot 操作到别的 bot 的页面 | 打开 New browser，由代码拒绝；默认引擎下只靠提示约束 |
| 数据 bot 一轮任务占用浏览器太久，评论和私信 bot 一直等 | 数据 bot 每轮只读一批；定时任务错开；避开评论高峰时段 |
| 回复内容不当 | 标为「需人工」的评论不自动回复；回复模板和禁用话术写进评论 bot 指令 |
| 小语种回复出错，店主看不出来 | 每条回复和私信附中文译文；只自动回复市场表里有的语言；报价、时效只用市场表里的说法，不让 bot 自己编 |
| 把有价值的评论漏判为普通互动 | 看板显示各类别的数量和抽样，店主每周抽查一次并调整分类标准 |
